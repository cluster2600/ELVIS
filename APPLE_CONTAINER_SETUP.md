# ELVIS Trading Bot - Apple Container System Setup

## Overview

This guide helps you run the **ELVIS Trading Bot** (Enhanced Leveraged Virtual Investment System) on macOS using Docker images optimized for Apple Silicon (M1/M2/M3) and Intel Macs.

> **Note**: This guide uses **Docker Desktop + docker-compose**. If you want to use
> Apple's native `container` CLI instead of Docker, see
> `APPLE_NATIVE_CONTAINER_GUIDE.md` and the `scripts/apple_container_native.sh` script.

## Features

### 🎯 **Trading Capabilities**
- **Paper Trading**: Start with $1000 USDT + $1000 BNB
- **Bonenkamp HFT Strategy**: 5-minute high-frequency trading
- **Ensemble Strategies**: Multiple trading algorithms
- **Multi-Asset Trading**: Support for BTCUSDT, BNBUSDT, and more

### 🏗️ **Container Architecture**
- **PostgreSQL**: Database for trade history and positions
- **Redis**: High-performance caching
- **ELVIS Bot**: Main trading engine
- **Prometheus / Grafana / Loki / Promtail**: Optional observability stack
  (behind the `observability` docker-compose profile)

### 🍎 **Apple Optimizations**
- ARM64 architecture support (Apple Silicon)
- Optimized memory usage
- Fast container startup
- Apple native `container` CLI support (see `APPLE_NATIVE_CONTAINER_GUIDE.md`)

## Quick Setup

### 1. **Run Automated Setup**
```bash
# Make setup script executable and run
chmod +x scripts/setup_apple_containers.sh
./scripts/setup_apple_containers.sh
```

The setup script generates three helper files in the repo root (they are not
committed): `docker-compose.apple.yml` (Apple Silicon resource overrides),
`start_elvis_apple.sh`, and `stop_elvis.sh`.

### 2. **Configure API Keys (Optional)**
Edit the `.env` file with your Binance testnet API keys:
```bash
# For paper trading, you can use testnet keys or leave empty
BINANCE_FUTURES_TESTNET_API_KEY=your_testnet_key_here
BINANCE_FUTURES_TESTNET_API_SECRET=your_testnet_secret_here
```

### 3. **Start ELVIS**
```bash
./start_elvis_apple.sh   # generated by scripts/setup_apple_containers.sh
```

### 4. **Access Dashboards**
- **Trading Dashboard**: http://localhost:5050
- **Grafana Metrics**: http://localhost:3001 (admin/admin) — requires the observability profile
- **Prometheus**: http://localhost:9090 — requires the observability profile

Prometheus, Grafana, Loki, and Promtail are behind the `observability`
docker-compose profile and are not started by default:

```bash
docker-compose --profile observability up -d
```

To reach the trading dashboard from the host, the API inside the container must
bind all interfaces (it binds `127.0.0.1` by default — see SECURITY.md). Set
`TRADE_API_HOST=0.0.0.0` in `.env.container`.

## Manual Setup

If you prefer manual setup:

### 1. **Build Containers**
```bash
# docker-compose builds the elvis-bot service from Dockerfile.minimal
docker-compose build

# Optional: standalone image from Dockerfile.simple (network-resilient variant)
docker build -f Dockerfile.simple -t elvis-bot:latest .
```

Both Dockerfiles are based on `python:3.14-slim`. The bot's runtime
configuration comes from `.env.container` (copy `.env.container.example` and
customize).

### 2. **Start Services**
```bash
# Start core services (postgres, elvis-bot, redis)
docker-compose up -d

# With the observability stack (prometheus, grafana, loki, promtail)
docker-compose --profile observability up -d

# Or with Apple optimizations (docker-compose.apple.yml is generated
# by scripts/setup_apple_containers.sh)
export COMPOSE_FILE="docker-compose.yml:docker-compose.apple.yml"
docker-compose up -d
```

### 3. **Initialize Paper Trading**
```bash
# Reset to initial balances
docker-compose exec elvis-bot python reset_paper_trading.py

# Check balances (script is excluded from the image, run it from the host)
POSTGRES_HOST=localhost POSTGRES_PORT=5433 venv314/bin/python check_paper_balances.py

# Or query the database directly
docker-compose exec postgres psql -U elvis_user -d elvis_trading \
  -c "SELECT * FROM np.account_balances;"
```

## Container Configuration

### **Services Overview**

| Service | Host Port | Purpose |
|---------|-----------|---------|
| elvis-bot | 5050, 8000 | Main trading engine and API |
| postgres | 5433 (container 5432, override with `POSTGRES_EXTERNAL_PORT`) | Trade history database |
| redis | 6380 (container 6379, override with `REDIS_EXTERNAL_PORT`) | Caching and data storage |
| prometheus | 9090 (`observability` profile) | Metrics collection |
| grafana | 3001 (`observability` profile) | Dashboards and visualization |
| loki | 3100 (`observability` profile) | Log aggregation |
| promtail | — (`observability` profile) | Log shipping |

### **Volume Mounts**
- `./logs` → Container logs
- `./models` → Trading models
- `./data` → Trading data
- `.env.container` → Environment configuration (loaded via `env_file`, not mounted)

### **Resource Limits (Apple Silicon)**
```yaml
elvis-bot:
  memory: 2GB
  cpu: 2 cores

postgres:
  memory: 512MB
  cpu: 1 core

redis:
  memory: 256MB
  cpu: 0.5 cores
```

## Management Commands

### **Container Management**
```bash
# View logs
docker-compose logs -f elvis-bot

# Stop all services
docker-compose down

# Restart services
docker-compose restart

# Update containers
docker-compose pull && docker-compose up -d
```

### **Trading Management**
```bash
# Reset paper trading
docker-compose exec elvis-bot python reset_paper_trading.py

# Check balances (run from the host; check_*.py scripts are excluded from the image)
POSTGRES_HOST=localhost POSTGRES_PORT=5433 venv314/bin/python check_paper_balances.py

# View open positions
docker-compose exec postgres psql -U elvis_user -d elvis_trading \
  -c "SELECT * FROM np.open_positions;"

# Test Bonenkamp strategy (run from the host; pytest is not installed in the image)
venv314/bin/python -m pytest tests/test_bonenkamp_strategy.py
```

### **Database Management**
```bash
# Connect to database
docker-compose exec postgres psql -U elvis_user -d elvis_trading

# Backup database
docker-compose exec postgres pg_dump -U elvis_user elvis_trading > backup.sql

# View trade history
docker-compose exec postgres psql -U elvis_user -d elvis_trading -c "SELECT * FROM np.trades ORDER BY timestamp DESC LIMIT 10;"
```

## Apple Native Container CLI

If you prefer Apple's native `container` CLI (https://github.com/apple/container)
over Docker, this repo ships dedicated tooling for it:

- `APPLE_NATIVE_CONTAINER_GUIDE.md` — full guide
- `scripts/apple_container_native.sh` — setup/start/stop helper
- `scripts/apple_container_elvis.sh`, `scripts/test_apple_container.sh`, `scripts/fix_apple_container_build.sh` — additional helpers

Note that the native CLI does not consume `docker-compose.yml`; the scripts above
manage the containers individually.

### **Performance Optimization**

For Apple Silicon (M1/M2/M3):
- Use `linux/arm64` platform
- Enable BuildKit for faster builds
- Set appropriate memory limits
- Use local volumes for better performance

## Troubleshooting

### **Common Issues**

1. **Docker not starting**
   - Ensure Docker Desktop is running
   - Check Docker permissions
   - Restart Docker service

2. **Database connection errors**
   - Wait for PostgreSQL to initialize
   - Check container health status
   - Verify network connectivity

3. **Memory issues on Apple Silicon**
   - Increase Docker Desktop memory
   - Adjust container limits
   - Monitor resource usage

4. **API key errors**
   - Verify testnet API keys
   - Check `.env` / `.env.container` file format
   - Ensure keys have proper permissions

### **Debug Commands**
```bash
# Check container status
docker-compose ps

# View container logs
docker-compose logs elvis-bot

# Connect to container
docker-compose exec elvis-bot /bin/bash

# Test database connection
docker-compose exec elvis-bot python -c "from utils.paper_trade_db import get_conn; print('DB OK' if get_conn() else 'DB Error')"
```

## Security Considerations

### **Container Security**
- Non-root user execution
- Read-only file systems where possible
- Network isolation
- Secret management through environment variables

### **API Key Safety**
- Use testnet keys for paper trading
- Never commit real API keys
- Use Docker secrets in production
- Regularly rotate keys
